**No, the skill package doesn't enforce that rule.** Nothing in the validator or the docs flags `_asset_type` or other private attributes, and nothing requires deriving types through `IdentifierType`. What exists: - **`scripts/validate_script.py`** has one private-access check, level 15 (`check_accessor_root_private_access`). It only warns on `._data["structuredData"]` and `._data["pageConfigurations"]`, and points to the accessor methods. Any other underscore attribute passes. - **`SKILL.md` and `references/`** mention `IdentifierType` as the return type of `create` and as the identifier type for `submit_requests`, but they never tell a script to avoid private attributes or how to get an asset's type without `_asset_type`. - **`cascade_cms/cmstypes.py`** is where the private access lives. `_asset_type` is set on the `Asset` class and read by its `asset_type`-style property. The validator doesn't scan for that. To enforce the rule, I'd add a validator check that flags any `Attribute` access whose name starts with `_` (excluding dunders) on an object that isn't `self`, and a `SKILL.md` line telling scripts to take the type from `IdentifierType` (`identifier.asset_type`, or the `.identifier` on a `create` result). I'd also add a template-level note. Want me to implement that?
