How does this current change to the `_PAGE_VIEW_CONFIG` affect the behavior of the basemodels `PageConfiguration` and `PageRegion`?
Sonnet 5.5 · Auto · 2026-09-29 21:30 UTC
First, a correction to the premise. `PageRegion` and `PageConfiguration` are no longer `BaseModel`s. They are `@pydantic_dataclass(config=_PAGE_VIEW_CONFIG)` classes. `_PAGE_VIEW_CONFIG` is `ConfigDict(populate_by_name=True)`, which I added in 3.7.0, not a change to an earlier config. The 3.6.0 `BaseModel` versions used `validate_assignment=True, from_attributes=True` instead. What that config does: - **`populate_by_name=True`:** each field is accepted under its snake_case name or its Cascade alias. `PageConfiguration(page_regions=...)` and `pageRegions=...` both work. The 3.6.0 model only accepted `pageRegions`. This mainly helps anyone constructing these objects by hand, for example in tests. The library itself always parses raw Cascade dicts, which use the aliases. - **No `extra` setting:** pydantic's default, `ignore`, applies. Unknown keys in a payload are dropped silently. That is why the old `content` key is ignored if it shows up. The raw dicts on the `Asset` are untouched, so `edit()` still round-trips every key. - **No `frozen`, no `validate_assignment`:** these are deliberately left unset. Read-only comes from the `__setattr__` and `__delattr__` overrides raising `ReadOnlyPageConfigError`. `frozen=True` wouldn't work here, because the dataclass machinery forbids a custom `__setattr__` on a frozen class and would raise a generic `FrozenInstanceError` instead of our message. - **Default lax validation:** a JSON list becomes the `page_regions` tuple. Field types still validate, which is why a config without `name` fails at `Asset` creation. - **`serialization_alias`:** it only takes effect if someone dumps with `by_alias=True`. Nothing in the library serializes these objects, since `edit()` uses the raw data. `from_attributes=True` is gone. Nothing in the library or tests relied on validating these from arbitrary objects.
